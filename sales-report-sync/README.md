# Slack の営業報告 → 顧客管理シート 自動転記

Slack の営業報告チャンネルに書かれた商談の結果を読み、営業管理シートの「顧客管理_Meta」「顧客管理_Threads」タブの J〜U 列に自動で転記します。スプレッドシートに組み込む Google Apps Script（`Code.gs` 1ファイル）で動きます。

## 何をするか

1. 30分ごとに、設定したチャンネルの親メッセージ（「19時広告面談入ります！」など）とスレッドの返信を読みます。
2. **投稿者（担当者）・投稿日・親メッセージの時刻** を、各タブの「担当者（I 列）」と予定日時（G・H 列、2回目は N・O 列、3回目は Q・R 列）に照らし合わせ、どの行の何回目の商談かを決めます。
   - お客様の名前は、Slack では本名、シートでは LINE の表示名のことが多いため、名前では照合しません。
   - チャンネルとタブの組み合わせは決め打ちしていません。両方のタブで照合し、一致した方に書きます（#ad に投稿されたスレッズ案件も Threads タブに入ります）。
3. 担当者の報告文を Gemini に読ませて、着座・結果・次回日時・プラン・理由を受け取ります。受け取った値はプルダウンの選択肢や日付の妥当性をコードで確かめてから書きます。
4. 書き込むのは **空欄のセル** と **このツールが前に書いたセル** だけです。人が入力した値と報告が食い違う場合や、判断に迷う場合は、書き込まずに「要確認」タブに回します。

## 転記のルール

| Slack の言い方 | 着座（L 列） | 結果（M・P・S 列） | ほかの列 |
|---|---|---|---|
| 未着座 | 飛び | 飛び | |
| 予定変更の依頼 | リスケ | 未実施 | |
| ブリッジ ○日○時 | 着座 | 保留 | 次回の予定日・時間 |
| 二回目調整（日時なし） | 着座 | 保留 | |
| 「○日まで検討」 → 後日「失注」 | 着座 | 保留 → 失注 | 同じスレッドの後からの返信で更新 |
| 失注／スクリーニング | 着座 | 失注 | |
| 言質（例: 「（プラン名）言質」） | 着座 | 成約言質 | プラン・金額 |
| 成約 | 着座 | 成約 | プラン・金額 |

- 着座の列は初回だけにあります。2回目・3回目は結果の列だけに書きます。
- 同じ日に時間を変えて実施した場合（例: 12時は未着座で、13時に実施）は、実際に実施した時刻を書きます。
- 報告に次にお客様と会う日時があれば、次の回の予定日・時間に書きます。成約言質のあとのローンや契約の手続き（例: 「27日15:00〜」）も含みます。3回目の次の予定は入れる列がないため、要確認に回します。
- T 列（プラン・金額）は、成約・成約言質のときに「プラン名 金額」の形で書きます（例: `プランA 300,000`）。報告に金額があればその金額を、なければ「設定」タブの金額を使います。
- U 列（失注・保留理由）には、Slack の報告に書かれている内容をもとに、理由と背景（お客様の状況、懸念点、検討状況、次の打ち手）を詳しく書きます。前に書いた理由がある場合は、それに今回の報告を足して書き直します。人が書いた理由は書き換えません。
- 推定でしか紐づけられない報告（日時に合う予定がない、候補が複数ある）は書き込まず、要確認に回します。
- 予定日を過ぎても結果の報告がない商談も、要確認に出します（日数は設定タブで変えられます）。

## 安全のための仕組み

- **見出しの確認**: 各タブの3行目の見出しが想定と違う（列がずれている）ときは、何も書かずに止まります。
- **行ずれの確認**: 書き込む直前にその行の LINE ID を読み直し、読み込んだときと違えば止まります。
- **人の入力を優先**: 「自動転記ログ」タブに、ツールが書いたセルと値を記録しています。今の値がログと違う（＝人が直した）セルは上書きしません。
- **同じ処理を繰り返しても安全**: 処理済みのスレッドは覚えていて、内容が変わったときだけ読み直します（編集にも気づけるよう、直近48時間のスレッドは毎回確認します）。
- **失敗しても次回に再挑戦**: Gemini の混雑や上限で読めなかったスレッドは、次の実行でもう一度試します。3回続けて失敗したら要確認に出します。
- **設定・接続の問題**: トークンが無効になった、チャンネルに招待されていない、などの問題は「要確認」タブに残し、Google からの失敗通知メールでも知らせます。

## 準備（最初の1回だけ）

### 1. Slack アプリを作る

1. https://api.slack.com/apps を開き、「Create New App」→「From scratch」を選びます。名前（例: 営業報告転記）とワークスペースを指定します。
2. 「OAuth & Permissions」の「Bot Token Scopes」に、次の3つを追加します。
   - `channels:history`
   - `groups:history`
   - `users:read`
3. 「Install to Workspace」でインストールし、表示される「Bot User OAuth Token」（`xoxb-` で始まる）をコピーします。
4. 報告を読むチャンネル（#ad-営業報告チャンネル、#threads-営業報告チャンネル）で、`/invite @営業報告転記` と送ってアプリを招待します。

### 2. Gemini の API キーを用意する

[Google AI Studio](https://aistudio.google.com/apikey) で API キーを作ります。**課金（請求先アカウント）を設定したプロジェクトのキーを使ってください。** 理由は次の2つです。

- 無料枠では、送った内容が Google のサービス改善に使われることがあります。報告にはお客様の情報が含まれます。
- 無料枠は上限が低く、止まりやすくなります。

費用の目安は、報告1件あたり1円未満です（gemini-2.5-flash の場合）。

### 3. スプレッドシートに組み込む

1. 営業管理シートを開き、「拡張機能」→「Apps Script」を開きます。
2. 最初からある `コード.gs` の中身をすべて消し、このフォルダの `Code.gs` の中身を貼り付けて保存します。
3. 左の歯車（プロジェクトの設定）→「スクリプト プロパティ」で、次の2つを追加します。
   - `SLACK_BOT_TOKEN`: 手順1でコピーしたトークン
   - `GEMINI_API_KEY`: 手順2の API キー
4. スプレッドシートを再読み込みすると、メニューに「自動転記」が出ます。

### 4. 動作を確かめてから始める

1. 「自動転記」→「接続テスト」を実行します。初回は Google の承認画面が出るので、アカウントを選んで許可してください（「このアプリは確認されていません」と出たら「詳細」→「（プロジェクト名）に移動」）。すべて ✅ になれば OK です。
2. 「自動転記」→「試運転（シートに書き込まない）」を実行します。「試運転結果」タブに、どのセルに何を書く予定かが出ます。一括転記済みの過去の分は「参考」と表示され、本番では処理しません。
3. 問題がなければ、「自動転記」→「定期実行を開始（30分ごと）」を押します。

## ふだんの使い方

- **報告の書き方は今までどおりで大丈夫です。** 次の点だけ守ってください。
  - 親メッセージに商談の時刻を入れる（「19時」「17時半」「10時30」「15:30」など）。
  - 結果はそのスレッドに返信する。
  - 次回の日時や、成約のときのプラン名を書く。
- **「要確認」タブ**: ツールが判断できなかった報告が並びます。シートを直したら「対応済み」にチェックを入れてください。
- **「設定」タブ**: 読むチャンネル、照合するタブ、プランと金額、報告なしとみなす日数を変えられます。
- **止めたいとき**: 「自動転記」→「定期実行を止める」。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 接続テストで Slack が ❌（invalid_auth など） | `SLACK_BOT_TOKEN` を貼り直す。アプリを再インストールした場合はトークンが変わります |
| チャンネルを読めない（not_in_channel） | そのチャンネルで `/invite @アプリ名` を送る |
| 権限が足りない（missing_scope） | 手順1の3つの権限を追加し、「Reinstall to Workspace」を押す |
| Gemini が ❌（400 / 403） | `GEMINI_API_KEY` を確認する。キーのプロジェクトで Gemini API が有効か確認する |
| 「列の見出しが…ではありません」で止まる | 列を足したり動かしたりしていないか確認する。見出しを元に戻すと再開します |
| 「Slack の名前「…」が担当者列にありません」 | Slack の表示名（氏名）と、シートの担当者（I 列）の表記をそろえる |
| 報告したのに反映されない | 親メッセージに時刻があるか、結果をスレッドに返信しているかを確認する。「要確認」タブに理由が出ていることがあります |

## 開発者向け

テスト（Node.js 18 以上）:

```bash
node sales-report-sync/test/run.js
```

Apps Script のサービスを擬似的に用意して、照合・書き込み・ログ・要確認・再実行の流れを確かめます。テストのデータはすべて架空のものです。このリポジトリは公開設定なので、コードやテストに実在のお客様の情報、スプレッドシートの ID、API キーを入れないでください（会社ごとの設定は「設定」タブ、キーはスクリプト プロパティに置きます）。
